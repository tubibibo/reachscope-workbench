# 场景包教学指南（教师用）

> **状态说明（先读这一段）**：本指南里的**场景包教案**（`missing-headers`、`cookie-flags`
> 两份 20 分钟教案）面向 **0.15.0 起可用的场景包机制**（内置包还有 `csrf-token`）。
> 如与实现不一致，以实现为准并在文档中修正。

## 1. 这份指南怎么用

- §2 是课前准备清单（今天 0.14.2 就要做的部分与 0.15.0 才需要的部分分列）。
- §3 是一节完整课（约 40 分钟）的流程与时间建议，适用于任何一课。
- §4、§5 是两份 20 分钟教案：`missing-headers`（安全响应头缺失）、`cookie-flags`
  （Cookie 属性）。**两份教案都标注了"0.15.0 计划中"**。
- §6 是学生常见提问；§7 是学习效果的观察点；§8 是实验室边界。
- 场景包本身的写法不在本指南里，见同目录的 `scenario-packs.md`（作者指南）。

## 2. 课前准备

|---|---|---|

### 2.3 不要做的事

- 不要把真实待测网站当课堂教具。实验室的意义就是"固定、可复现、零外部影响"。
- 不要让学生把课堂方法对准学校网络以外的主机——那超出本工具的授权模型（见 §8）。

## 3. 一节完整课的流程（约 40 分钟）

适用于任何一课；下面以"响应头缺失"为内容举例。每步给出时间建议与验收动作。

| 阶段 | 时间 | 做什么 | 验收动作（做到位的样子） |
|---|---|---|---|
| 课前准备 | 课前 1 天 + 课前 10 分钟 | 按 §2 清单装机、断网、预跑一遍；学生机提前开机 | 教师机 10 分钟内能从开机走到"两次采集都在屏幕上" |
| 演示 | 8 分钟 | 教师完整走一遍闭环：启动 → 采集 baseline → 应用一处明确的加固（切 hardened）→ 对同一 URL 复测 → 逐字段对比 → 人工关闭。边走边说"每一步在屏幕上对应什么" | 学生能指出"哪一步改变了结果" |
| 学生动手 | 15 分钟 | 学生在自己的实例上重复同样的闭环。要求：先写下预测，再采集 | 每个学生至少完成两轮"预测 → 采集 → 核对" |
| 对比 | 10 分钟 | 全班对齐同一张对比表：同一 URL、两个剖面、逐字段看变化。让学生轮流读出"哪个字段从什么变成什么" | 对比表由学生口述填出，不是教师贴出来 |
| 小结 | 5 分钟 | 收束到两句话：① 安全响应头是"默认缺失"的，要显式配置；② 缺头是观察，修复要以复测证据为准 | 学生能复述这两句，并说出至少一条实验室边界 |

节奏提示：演示阶段最容易超时。演示时只点对比表里**两三个**字段，其余留给学生动手阶段
自己发现，课堂效果更好。

### 3.1 今天（0.14.2）就能上的近似课

0.14.2 的内置实验室本身就是一个"响应头缺失"演示：

- baseline（初始版）响应带有：`Content-Type: text/html; charset=utf-8`、
  `Cache-Control: no-store`、`Referrer-Policy: unsafe-url`，以及 `X-ReachScope-Lab-*`
  标识头（会话/代次/剖面）。
- hardened（响应头补强版）在此之上发送四类加固头：
  `Content-Security-Policy: default-src 'none'; base-uri 'none'; frame-ancestors 'none'; form-action 'none'`、
  `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`。
- `Referrer-Policy: unsafe-url` 在 baseline 里**不是 bug**，是刻意的教学差异：让"策略宽松"
  与"策略收紧"形成真实可观察的对比。
- 0.14.2 的局限：页面只有 `/` 一条路径、只支持 `GET`、**不演示 Cookie 与 TLS/HSTS**
  （`_LIMITATIONS` 原文见 §8）。

### 3.2 与 0.15.0 场景包课堂的差别

| 维度 | 0.14.2（现在） | 0.15.0 场景包（计划中） |
|---|---|---|
| 可上的课 | 响应头缺失（近似） | 每个场景包一课；内置 3 个（安全头、Cookie、CSRF） |
| 加一课 | 改 Python 代码 | 放一个目录（YAML + 静态页面），重启生效 |
| 页面内容 | 固定英文页面 | 每包自带静态页面与 `walkthrough.md`（学生讲义） |
| Cookie 演示 | 无 | `cookie-flags` 包（见 §5） |

## 4. 20 分钟教案 A：`missing-headers`（安全响应头缺失）

> **状态：0.15.0 计划中。** 场景包行为按场景包的规格：baseline 只有
> `Content-Type`；hardened 增加 `X-Content-Type-Options: nosniff`、
> `X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`、
> `Content-Security-Policy: default-src 'none'`。

**教学点**：安全响应头是"默认缺失"的——不配置就没有，浏览器按最宽松的方式处理。

| 时间 | 环节 | 教师 | 学生 |
|---|---|---|---|
| 0–2 分钟 | 边界声明 | 一句话讲清：站点只跑在本机回环、响应是固定内容、随时可停；然后启动实验室 | 打开实验室页面，确认地址栏是 `127.0.0.1` |
| 2–6 分钟 | baseline 采集 | 让学生把实验室地址作为网站资产采集一次（页面提供现成模板），看返回的响应头 | **自己逐行读出**收到的头，数一数有几个安全头（答案：0 个） |
| 6–10 分钟 | 切 hardened 复测 | 教师只说一句："现在应用加固，对**同一条 URL** 再测一次。" 强调对比的前提是同 URL | 复测，把两次的头并排写在纸上 |
| 10–15 分钟 | 逐字段对比 | 让学生轮流指认"新出现的头"，并给每个头配一句话"它防什么"（提示可用 `scenario-packs.md` §5 的白名单表） | 完成配对：`X-Content-Type-Options` → 防类型嗅探；`X-Frame-Options` → 防被嵌入 iframe（点击劫持）；`Referrer-Policy` → 防 Referer 泄露；`Content-Security-Policy` → 限制资源加载来源 |
| 15–18 分钟 | 预测游戏 | 让学生先写"如果切回 baseline，对比表里哪些格子会变空？"再切回去验证 | 预测 → 验证，错的地方当场讨论 |
| 18–20 分钟 | 小结 | 两句话收束：① 缺头是默认状态；② 加头是补一层配置，不等于"修好了应用" | 复述 + 说出至少一条边界 |

**常见误区（要主动讲）**：

- "加了头就安全了。"——头是纵深防御的一层。`X-Frame-Options: DENY` 挡嵌入，不挡 XSS；
  CSP 限制资源来源，不修复有漏洞的代码。复测只证明**响应变了**，不证明应用没有其他问题。
- "没出现的头说明工具漏检了。"——没观察到 ≠ 不存在，但在这个实验室里，固定响应里
  没有就是没有；这正是它适合教学的原因。

## 5. 20 分钟教案 B：`cookie-flags`（Cookie 属性）

> **状态：0.15.0 计划中。** 当前 0.14.2 实验室**不发送任何 Cookie**，这堂课在 0.14.2
> 上不了。场景包行为按场景包的规格：baseline 的 cookie 是
> `session=demo123; Path=/`；hardened 是 `session=demo123; Path=/; HttpOnly; Secure; SameSite=Lax`。

**教学点**：Cookie 的每个属性各防什么——`HttpOnly`、`Secure`、`SameSite`、`Path`。

| 时间 | 环节 | 教师 | 学生 |
|---|---|---|---|
| 0–2 分钟 | 边界声明 | 同教案 A；另说明：这节课会用到浏览器的 Cookie 存储，仍在本机回环上 | 选中场景 `cookie-flags`，启动 |
| 2–5 分钟 | baseline 观察 | 让学生**在浏览器地址栏直接打开**实验室地址（它是一个真的本机站点），再打开 DevTools 的 Application/存储面板看这条 cookie | 找到 `session=demo123`，记下它现在有哪些属性（只有 `Path=/`） |
| 5–8 分钟 | `document.cookie` 实验 | 让学生在这页的 Console 里输入 `document.cookie` | 能读到 `session=demo123`——即页面里的任何脚本都能读它 |
| 8–12 分钟 | 切 hardened 复测 | 切到 hardened 剖面，重新打开同一 URL；对比 DevTools 里属性列的变化 | 看到新增 `HttpOnly`、`Secure`、`SameSite=Lax` |
| 12–16 分钟 | 属性配对 | 逐个属性问"它防什么"：`HttpOnly` → 挡脚本读取（缓解 XSS 窃取 cookie）；`Secure` → 限安全通道传输；`SameSite=Lax` → 限制跨站请求携带（缓解 CSRF）；`Path=/` → 作用域。让学生再跑一次 `document.cookie` | 发现 `session` 读不到了——**这不是 cookie 坏了**，是 `HttpOnly` 生效 |
| 16–18 分钟 | 预测游戏 | "如果只去掉 `HttpOnly`，哪个实验会变结果？"先写预测再验证 | 预测 → 验证 |
| 18–20 分钟 | 小结 | 两句话：① 属性是逐个收紧的，缺一个就少一层；② 属性是缓解，不是修复——`HttpOnly` 挡得住脚本读，挡不住网络层已经发出去的请求 | 复述 + 说出至少一条边界 |

**两个值得主动讲的技术诚实点**：

- 浏览器把回环地址（`127.0.0.1`）视为可信来源，所以在本实验室的纯 HTTP 上
  `Secure` cookie 也能被设置并生效；公网上的纯 HTTP 站点则不行。这正好说明
  `Secure` 属性防的是"传输层降级"，不是"本机"。
- 文法只允许 `Path=/`（见 `scenario-packs.md` §7），所以这堂课不涉及多路径作用域；
  有人问就如实说：实验室只服务固定路径，教学文法把 `Path` 固定成了一种写法。

## 6. 学生常见提问与回答

1. **"它会联网吗？会碰到我的真实网站吗？"**
   不会。实验室只监听 `127.0.0.1` 的随机端口，响应是项目内置的固定内容；场景包加载
   过程没有任何网络调用。可以当堂断网验证。
2. **"为什么每次采集结果一模一样？是不是假的？"**
   是真的 HTTP 响应，只是内容固定。确定性正是它能用于对比和教学的原因——每次结果一致，
   课堂演示的因果才固定。（`Date` 头每秒都会变，但它由 HTTP 服务自动生成，不属于
   证据字段。）
3. **"缺这些头算漏洞吗？"**
   算观察，不算已确认漏洞。缺失的响应头是一个可以核实的配置事实；它是否构成安全问题
   取决于应用怎么用这个页面。工作台也从不自动给整个资产下"安全"的结论。
4. **"加了安全头是不是就安全了？"**
   不是。响应头是纵深防御中的一层：`X-Frame-Options` 挡嵌入、CSP 限制资源来源、
   `HttpOnly` 挡脚本读 cookie。后端逻辑的问题要修后端；复测只证明响应层面变了。
5. **"为什么改路径是 404、用 POST 是 405？"**
   0.14.2 的实验室只回答 `GET /`：这是它的固定行为，不是故障。0.15.0 的场景包可以有
   最多 32 条路由（计划中），但方法仍然只有 `GET`。
6. **"`HttpOnly` 的 cookie 在 DevTools 里还能看到，那它挡住了谁？"**
   挡住的是**页面脚本**：`document.cookie` 读不到它，所以 XSS 偷不走它。DevTools 是
   浏览器给你的检查视角，不是页面脚本，两者不是一回事。
7. **"我能自己写一个场景包吗？"**
   0.15.0 的设计目标就是让你能：一个目录、一个 YAML、几个静态页面，不改代码。
   机制是**计划中**的；写法见 `scenario-packs.md`。
8. **"HSTS 头在这里怎么没效果？"**
   因为实验室是纯 HTTP 回环，浏览器不会对 HTTP 响应生效 HSTS。在白名单里保留它
   是作为配置演示；真实站点上它要配合 HTTPS 才有意义。

## 7. 怎么判断学生真的学会了（观察点，不是考试题）

在动手与对比环节巡场，逐个观察。能在无提示下做到的条数，就是掌握程度。

| # | 观察点 | 达标表现 |
|---|---|---|
| 1 | 指认变化 | 能指着对比表说出"哪个头从无到有、值是什么"，而不是笼统说" hardened 更安全" |
| 2 | 头 → 防御对象配对 | 能给每个变化的头配一句"它防什么"，且不夸大（说得出"缓解"而不是"防住"） |
| 3 | 预测先行 | 复测前先写预测、复测后核对；预测错了会回去看证据，而不是改口 |
| 4 | 同 URL 自觉 | 明白对比的前提是"同一条 URL、两个剖面"；发现 URL 不一致会主动提出 |
| 5 | 观察与结论分开 | 能说清"缺头是观察"，不会当堂宣布某个站点"有漏洞"或"安全" |
| 6 | 边界复述 | 能说出至少一条实验室边界（回环 / 固定响应 / 不出网） |
| 7 | Cookie 课专属 | 能演示 `document.cookie` 在 `HttpOnly` 前后的差别，并解释这不是"cookie 坏了" |
| 8 | 伦理边界 | 主动问到"能不能拿这个去测别的网站"时，知道答案是否定的，并说得出原因（无授权、工具也不是为这设计的） |

不需要笔试。上面 1–4 是技能，5–8 是判断力；一个学生在巡场中被看到 4 条以上，本课
目标即达成。

## 8. 实验室的边界

### 8.1 边界一览

| 边界 | 内容 |
|---|---|
| 回环绑定 | 只监听 `127.0.0.1`，随机端口；不给局域网/公网提供服务 |
| 固定响应 | 响应是项目内置/场景包声明的固定内容，不代表生产网站 |
| 不联网 | 不发起任何出网请求；没有在线场景市场、没有自动下载（项目明确不做） |
| 不产生真实流量 | 所有请求都发往本机回环，不出网卡、不接触本机以外的任何目标；学生用浏览器直接打开实验室地址也一样 |
| 不写访问日志 | 实验室不记录访问日志（现状不变） |
| 不是漏洞靶场 | 不提供可利用漏洞，只提供配置差异（项目明确不做） |
| 单场景运行 | 同一时刻只有一个场景在跑；切换 = 停掉当前，以新代次（generation）重启（0.15.0 计划中） |
| 方法与路径 | 0.14.2：只有 `GET /`；其他方法 405、其他路径 404、Host 不符 421。0.15.0 场景包：最多 32 条路由，方法仍只支持 `GET` |

### 8.2 产品自己的边界声明（原文照录）

以下是 0.14.2 实验室随状态返回的 5 条限制声明（`integrations/local_lab.py` 的
`_LIMITATIONS`，逐字引用），课堂上可以直接投影给学生：

> - 本地教学场景只监听 127.0.0.1 的随机端口，响应是项目内置的固定内容，不代表生产网站。
> - 启动或切换版本不会执行检查、调用 AI、创建发现或关闭事项；请保存资产并明确选择检查。
> - 补强版只演示四类 HTTP 响应头，不代表完成应用安全审计；此 HTTP 场景不演示 TLS/HSTS。
> - 停止或重启服务会结束本场景；历史证据仍保留，旧地址不会自动重新启动或转向其他目标。
> - 切换版本会影响后续请求；已保存证据不改变，执行中的请求以实际捕获的响应为准。

### 8.3 课堂纪律建议

- 所有实验只对准本机回环。不把课堂方法对准学校网络以外的主机——既无授权，工具的
  授权模型也不支持。
- 工作台保存的证据可能包含页面文本，留在本机 `--data` 目录里；课后不需要的实例
  直接停止即可，不必清理到"零痕迹"。
- 停止或重启会结束当前场景；历史证据保留。0.15.2 的"课堂重置"（计划中）会把这个
  动作做成显式功能，在那之前用"重启应用"当作重置。
