# 第一次使用：从一个资产开始

## 启动

Python 3.11+。发行包已包含前端，使用时不需要 Node.js。

Windows 在项目目录运行 `./start-workbench.ps1`；其他环境安装后运行：

```sh
python -m venv .venv
# 按当前系统激活虚拟环境后：
python -m pip install .
reachscope-workbench doctor --data .workbench
reachscope-workbench serve --data .workbench --port 8765
```

打开 `http://127.0.0.1:8765/#/guide`。服务只监听本机，关掉终端会停止服务。
`doctor --json` 可输出自动化可读的本地检查；不建立工作区、不联系目标或模型。
Java/Apktool 缺失只影响真实 APK，不阻止 Web、云配置、主机资料和源码样例。
自检不证明端口、工作区锁、数据库迁移或网络一定正常；执行任务前仍有单资产预检。

## 先亲手走完本地闭环

进入 `http://127.0.0.1:8765/#/lab`，逐项启动、保存资产、执行基线、选观察建立事项、
切换固定补强配置、复测并填写依据后人工关闭。每一步由你明确触发，不自动扫描或调用 AI。
这是受管 loopback 网站的实际采集，单独标为本地教学；不代表生产资产结论。
停止后证据保留，站点本身不跨重启恢复。详见 [教学说明](local-lab.md)。

## 选一个入口

| 手上的资料 | 操作 | 结果边界 |
|---|---|---|
| 网站网址 | 上手指南 → 网站 → 提供完整 HTTP(S) 地址 → 选择检查 → 确认 | 只观察明确地址；配置线索不是漏洞确认 |
| Android APK | 上手指南 → Android → 上传 APK → 选择检查 | 静态分析，不运行 APK；真实文件需要 Java/Apktool |
| AWS 配置 JSON | 上手指南 → 云资产 → 配置文件 → 上传支持格式 | 离线查看网络/IAM/存储字段，不读取云账户 |
| 云服务器 HTTP(S) 地址 | 云资产 → 服务地址 | 外部 Web 观察，不能据此得知安全组或 IAM |
| 主机 SSH/Nginx 配置 JSON | 主机防御 → 配置基线 → 下载模板并上传资料 → 预览 → 选择检查 | 只解释提供的配置；主机标识、连接上下文和时间由操作者声明，不证明运行态 |
| 尚未准备主机配置资料 | 同一入口下载可审阅采集器 → 在 Linux 预览计划 → 明确确认导出 → 手动上传 JSON | 无自动提权、上传或修复；不支持/失败保持未知，详见 [采集说明](../modules/host/collector.md) |
| Nginx 或 OpenSSH 日志 | 主机防御 → 访问日志/认证日志 → 上传 `.log` 或 `.txt` | 有限样本产生复核线索；缺少年份/时区保持未知，无命中不能证明安全 |
| 暂时没有自己的资产 | 主动选择内置样例 | 合成输入会保留标签，不替代实际测试 |

先看任务是否完成，再看「本次执行范围」和证据。把要跟进的线索放入「验证与整改」，
记录负责人/处理意见；完成新的可比检查后，再填写复测依据。失败、未知或资源消失
不会被算成修复。刷新或重启保留已保存记录，重试建立新的检查记录。

## 可选 AI

基础流程不用 AI。需要时进入「AI 接口」，选择 DeepSeek、OpenAI 兼容或自定义服务，
填服务商给出的 **API 基址、准确模型名和自己的密钥**。支持的是 Chat Completions
协议，不是所有厂商的原生 API；模型权限、计费和可用性由服务商决定。

先「诊断当前地址」：它只发送无密钥 GET，不调用模型，也不能证明账号/余额/模型
可用。保存设置后可另行勾选目录读取授权，只向该保存地址带凭据 GET /models；
目录可见不代表推理权限或计费状态正常。保存配置同样不会调用模型。只有已完成的真实网站检查可在「AI 研判」预览
脱敏摘要，再明确确认发送。默认推理强度让服务商自行决定，避免把 GPT 参数强塞给
其他模型；兼容端点可按实际协议选输出预算字段。请求不自动重试。

密钥只留在服务端本次运行内存，重启需要重新输入（显式环境变量另见 AI 文档）。
换服务商或基址时，旧密钥不会跟过去。诊断连接失败时先检查服务商状态/基址/网络，
不要关闭 TLS 校验或防病毒软件来绕过错误。详见 [AI 使用与边界](../modules/web/ai-advisory.md)。

## 出问题时

记录页面错误码/请求标识、操作入口、模块及任务 ID，检查 [项目状态](../releases/project-status.md)。
提交 GitHub Issue 前移除密钥、Cookie、私有源码、真实资产和工作区数据库。不要上传
`.workbench/`，不要把完整模型原始响应当成公共诊断材料。

## Web 结果中的实施指南

已保存的成功网站检查可直接打开「配置实施指南」，无需 AI。先看原检查状态和证据，
再阅读前提、人工核查、补强、复测和回滚；未采集或未知不能算成问题。
若自己确认部署使用 Nginx，可选择参考片段；工作台不检测其版本，也不执行配置。
升级前停止服务并备份；当前工作区 schema 7 的回退要求见 [工程门禁](../development/quality-gates.md)。
