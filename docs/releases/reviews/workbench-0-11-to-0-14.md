# 0.11–0.14 工程审查结论

0.11 的教学整改流程将案例请求限定为明确的来源字段，修复完整候选对象序列化导致的 422；
任务与资产保留不可变来源、幂等重放和升级后的历史数据。持久化复核修复上传时 SQLite
写锁阻塞事件循环、分页参数溢出和早于基线完成的采集被误用为复测的问题。0.14 将主机
资料准备拆为固定进程执行、最小字段投影、计划确认与手动导入；HTTP 只提供许可齐全的
源码下载，不执行采集。失败采集、执行权限、输出路径绑定、进程回收和迟到响应使用
有界且可审计的失败语义。0.14.1 的目录整理迁移 95 个受控路径，保持 API、业务规则、
版本号及 schema 7；核心与框架/适配器、各模块之间继续保持依赖边界。

已知风险包括单机 SQLite 工作区的备份与断电边界、开发依赖 minimatch 的未关闭公告，
以及静态资料与运行态之间的差距。红蓝视角不代表身份认证或权限隔离；操作者提供的
主机标识、时间和版本没有被认证。投影资料不是可部署配置，日志无命中不能清除事项，
缺失、失败、未知或不可比的证据不能支持“已整改”。模型目录诊断不等同于推理成功，
付费请求需要独立授权，不自动重试含糊结果。

历史目录整理验收记录为 2033 passed、5 skipped、92.44% coverage、211.57s；严格 mypy
覆盖 129 个源文件，八组浏览器门禁包含 76 项检查。局部测试有重叠，不能相加为总数，
旧 helper 导入失败的首轮记录也不能算作通过。当前能力及可复现命令见
[项目状态](../project-status.md)、[验证记录](../validation/workbench.md) 和
[质量门禁](../../development/quality-gates.md)。真实 Linux 进程/权限/符号链接与实际
sshd/nginx、真实 APK/JAR、商业 AI 推理、外部目标扫描及远程 CI 仍不能由 Windows mock
或本地协议桩证明；公网、多租户、生产高可用和外部可信时间戳也不在已有保证内。

后续工作应以固定来源契约、完整证据、受控失败和人工复测为基础，优先选择一个蓝队
报告格式完成离线导入与事项处理，再考虑在线采集或外部引擎。工作区一致性盘点与备份
机制、真实提供商及实际平台验收分别设计，避免扩大未经验证的声明。目录维护以
[仓库规则](../../development/repository-layout.md) 和
[路径迁移表](../../../config/path-migrations.json) 为准；历史结果仅用于来源追溯，
不构成安全认证、无缺陷保证或任何组织的架构师职级评定。
