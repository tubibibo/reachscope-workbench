# 产品定位与 0.14 取舍

2026-11-02。面向开发者、安全学习者和蓝队个人使用者；求职作品与开源交付。

ReachScope 是**安全加固、证据复核与整改验证工作台**。蓝队成为日常处理主线：
提供资产资料、明确范围、执行可解释检查、核对证据、记录处理决定、复测与人工关闭。
红队保留为授权验证视角。Android 是应用安全输入，Web、云和主机资料提供互补证据。

## 已实现的落点

- 原有 Android/Web/云模块、持久任务、证据、修订文件与人工复测保留。
- 第四个 host 模块离线处理操作员提供的 SSH/Nginx 配置和有限格式日志。
- 7 条配置规则保留上下文、未知和原始资料摘要；3 条固定窗口日志规则只产生复核线索。
- 主机输入有稳定标识、模板和执行前预览；日志结果保留行号、时间和来源别名，排除原始请求/用户名。
- 处理人、期限、风险接受、误报说明和审计机制沿用现有整改用例。
- AI 仍为可替换的辅助适配器，仅 Web 试点；真实商业推理继续未验证。
- 0.14 增加独立标准库采集器：固定命令、计划摘要确认、最小字段投影和手动上传。
- 采集元数据独立校验，失败或语义缺口不变成安全通过；v1/v2 比较范围保持区分。
- 主机结果可直接进入已有工作区/案例，用步骤导航完成修订、复测和人工结论。

## 当前边界

本地单人、模块化单体，拥有自己的 React 前端与 FastAPI 接口。没有终端 Agent、
实时日志流、远程采集/命令、自动封禁、多租户隔离或生产 SOC 运行验收。
有限日志无命中不能证明未被攻击，也不能用来清除整改案例。配置通过仅针对已提供
资料，真实部署、业务影响、主机身份与连接上下文仍需管理员核对。

## 后续顺序

Linux 实机方向保持暂停，现有采集器及未验收记录保留，不再将安装或
推进 Linux 环境作为下一步。优先研究成熟 GitHub 蓝队工具的报告接入：Windows
事件调查、云安全检查以及软件/依赖风险。当前推荐先选一个固定版本/输出契约，
完成上传、解析预览、字段投影、来源证据与人工事项；再考虑外部引擎执行或远程接口。
具体候选、许可和取舍见 BLUE-TOOL-INTEGRATION-RESEARCH.md。2026-11-02 的工作仅为调研，未实现
这些适配器，也不把已有通用 JSON/JSONL 导入说成已兼容相应工具。

Linux 实际二进制门禁继续是未执行的历史边界，不能把 mock、Windows 单测或受控
上传冒充实机采集。跨工具归并、重复问题重现、自动采集及更多日志源均需独立设计
和验收。可追溯与可复核的结果是质量指标。

框架仍遵循 core 不依赖 HTTP/具体模块/外部服务、显式模块注册、不可变任务快照、
有界队列、失败保留、凭据隔离和人工关闭。schema 7 阻止旧版本错误解释新增 host 语义；
升级前备份，回退需恢复与旧版本匹配的工作区资料。

当前能力与实际测试见[项目状态](../releases/project-status.md)。
